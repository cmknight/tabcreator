# storage/ — sole owner of IndexedDB, OPFS, navigator.storage and localStorage (prefs.ts) (spine AD-2); imports model/ only (AD-1).

db.ts `importTakes` (story "Restore from a backup", 6.6) writes whole records as given (writer `restore`, no `updatedAt` stamp) in one transaction, skipping any take id already stored (its record and tab are never overwritten), resolves to the number written and always emits one `library-restored` with that count. restore.ts reads a backup zip through the backup worker's `read` request (backup-worker.ts stays the only importer of fflate) and `validateBackup` checks the manifest and every audio entry in full before anything is written; any unreadable or invalid file is `backup-invalid`.

persistence.ts (story "Storage protection and Library states", 6.7) owns `navigator.storage`: `requestPersistOnce()` (persist() at most once per page load, only when `persisted()` is false; recording-session calls it after a take is saved, by a stop or a recovery Open), `persisted()` (false when the API is missing or throws; waits for a request in flight) and `estimateUsage()` (`estimate().usage`, null when unknown); none throws. It also keeps the storage-full status, with its own `subscribeStorageFull` (not a `StorageEvent`): write-guard.ts `toStorageError` sets it on every `storage-full` result, a write's or a read's (QuotaExceededError, and the dev hooks, session/'s analysis hooks too through it), remembering the take the operation was for when known. A committed save of any other take clears it (persistence.ts listens to events.ts: `take-put` or `tab-put` for another take id, or `library-restored`); the failing take's own saves (its storage-full stop, its analysis commit) do not. It is in memory only: it survives navigation, not a reload. Dev builds: `window.__storageFullSaveHook` (dev/hooks/storage-full.ts) makes `writeCompressed`, `patchTake` and `putTab` reject `storage-full` through `assertDevSaveSpace` until cleared.
