# storage/ — sole owner of IndexedDB, OPFS, navigator.storage and localStorage (prefs.ts) (spine AD-2); imports model/ only (AD-1).

db.ts `importTakes` (story "Restore from a backup", 6.6) writes whole records as given (writer `restore`, no `updatedAt` stamp) in one transaction, skipping any take id already stored (its record and tab are never overwritten), resolves to the number written and always emits one `library-restored` with that count. restore.ts reads a backup zip through the backup worker's `read` request (backup-worker.ts stays the only importer of fflate) through `runBackupWorker` in backup.ts, the worker lifecycle backup and restore share (start, error and unreadable-reply rejections, terminate once settled) and `validateBackup` checks the manifest and every audio entry in full before anything is written; any unreadable or invalid file is `backup-invalid`.

persistence.ts (story "Storage protection and Library states", 6.7) owns `navigator.storage`: `requestPersistOnce()` (persist() at most once per page load, only when `persisted()` is false; recording-session calls it after a take is saved, by a stop or a recovery Open), `persisted()` (false when the API is missing or throws; waits for a request in flight) and `estimateUsage()` (`estimate().usage`, null when unknown); none throws. It also has `hasRoom()` (free space `quota − usage` ≥ min(`ROOM_FRACTION` (5%) of the quota, `ROOM_BYTES` (500 MB)); null when unknown) and keeps the storage-full status, the one source Record and the Library read, with its own `subscribeStorageFull` (not a `StorageEvent`): write-guard.ts `toStorageError` sets it on every `storage-full` result, a write's or a read's (QuotaExceededError, and the dev hooks, session/'s analysis hooks too through it), and `recheckStorageFull()` (main.tsx, at start-up) sets it when there is no room. Only space the player frees clears it: `beginFreeing()` at the start of a `db.deleteTake` with writer `library-session` (recording's and recovery's automatic deletes, and a take that did not exist, do not clear it) and of library-session's `deleteAudio`, then its `freed(removed)` once the files are removed (cleared when every removal succeeded and no new `storage-full` landed meanwhile, then a room re-check, not awaited, which only clears), or a start-up re-check showing room. A rename, a new take, an analysis or edit save and a restore never clear it; an unknown estimate neither sets nor clears it. It is in memory only: it survives navigation; a reload re-checks. Dev builds: `window.__storageFullSaveHook` (dev/hooks/storage-full.ts) makes `writeCompressed`, `patchTake` and `putTab` reject `storage-full` through `assertDevSaveSpace` until cleared.

paths.ts holds `AUDIO_DIR` (the compressed-audio directory, in OPFS and in a backup zip) for audio-store.ts, backup.ts, restore.ts and backup-worker.ts. It is a leaf module with no imports, so sharing it pulls neither fflate, a worker nor the audio store into another bundle (the OPFS worker's build also compiles audio-store.ts).
