# session/ — one store per aggregate plus analysis.ts, instance-lock.ts (sole owner of Web Locks and BroadcastChannel) and app-reload.ts (spine AD-2, AD-3); may import model/, storage/, engine/ and audio/.

recording-session.ts composes its input derivations through input-derivation.ts: level-watch.ts (level warning), input-quality-watch.ts (input quality warning) and tuner-watch.ts (Tuner reading and ticks); none imports another or the store.

recording-recovery.ts is a module of recording-session.ts (story 3.11): the start-up recovery scan, Open and Discard of unfinished takes; the store composes it and publishes its list as `recovered`.

take-lifecycle.ts is a module of recording-session.ts: the take in progress and the recording state machine (start, count-in, chunks, length limits, failure stops, the save). take-save.ts holds what recording and recovery share: `MIN_TAKE_MS` and its one test `isTooShort`, the clip counter and the save step. The store's `isBusy()` is the one busy answer for its `beforeunload` guard; app-reload.ts's `isAppBusy()` (story 5.7) adds `analysis.isAnalysing()` and is the one busy answer for every app reload (Settings' and the Tab screen's Reload, and the update toast later). `beforeunload` does not ask while analysing: an analysis interrupted by a reload starts again when its Tab opens.

instance-lock.ts gates the app on the Web Lock and hands it over (story 3.10); after a steal the new holder's recovery scan waits for the old holder's `released` message (story 5.3), with a 30 s fallback.

analysis.ts runs a take's analysis (story 5.6): PCM → engine analyze → mapFrets → one `commitAnalysis`, then the raw file is deleted. Runs live in a module-level registry keyed by take id, so a run outlives the session that started it; `isAnalysing()` feeds app-reload.ts's busy check. Its only caller is take-session.ts. The PCM source (ticket 12, AD-15): the raw file; when `readRaw` rejects `audio-missing`, the compressed audio decoded by `audio/decode.ts` at the take's recorded rate (`take.sampleRate`, not the file's native rate: `decodeAudioData` resamples to it), and the engine gets the decoded buffer's rate; with neither (no raw file, and no compressed file or `audioMime` null) the run rejects `audio-missing` (Analysis failed). Decoded audio is never written back and the raw file never recreated; the post-commit `deleteRaw` is skipped for a decoded take. Takes saved by failure stops (mic-lost, storage-full, instance-lost, recovered) are `recorded` like any other and analyse when their Tab opens. Story 5.7: `cancel` settles a run at once with `analysis-cancelled` (the engine worker restarts); a `storage-full` commit keeps the built result in memory as a pending commit (not busy) for `retryCommit`, dropped when the take is deleted or analysed again. Dev builds hold every analysis with `?holdAnalysis` (e2e tests that read a stopped take's raw file or `recorded` status), delay each engine analyze with `?slowAnalysis=<ms>`, and force failures with `window.__analysisFailHook` (`analysis-failed`) and `window.__commitStorageFullHook` (`storage-full` on commit); production builds tree-shake all of them. Story "Analysis settings and re-analysis" (US-4.6): `reanalyse(take, onProgress)` reads the PCM the same way, runs the engine with the take's current settings, trim and count-in skip (progress 0–0.9), and returns the result, the engine version and whether the raw file was read; it commits nothing. It is cancelled by `cancel(takeId)`, counts in `isAnalysing()`, and is cancelled when its take is deleted.

Dev hooks: the readers and state behind every dev-only e2e hook (`__recordingClock`, `?maxTakeMs`/`?warnLeadMs`, the analysis hooks above, `__instanceTest`, `__encodePcmFailHook`; storage/'s `__storageFullHook` and ui/'s `__playbackTrace` too) live in `src/dev/hooks/`. Production modules import them statically and call them only inside `import.meta.env.DEV`, so production builds tree-shake them; the CI dist grep checks.

take-session.ts is the Tab screen's store, one per open take (story 5.6): it loads the take and tab, calls `ensureAnalysed` for a `recorded` take and publishes progress, then the committed take and tab; it handles storage events per AD-5. `dispose()` detaches without cancelling the analysis. Story 5.7: `cancel()`, `analyse()` (Analyse and Retry) and `retryCommit()`; a cancelled run stays cancelled for the session, and a new session analyses a `recorded` take again. Story "Tab screen, reflow and selection": `selectedNoteId` with `select`/`selectNext`/`selectPrev` (played order, kept by note id, cleared when the note is gone) and `rename(title)` (`patchTake` as `take-session`, published locally); `setActiveTakeSession`/`activeTakeSession` hold the mounted Tab screen's session for the ←/→/Esc shortcuts. Story "Flags, warnings and bar lines on screen": `selectNextFlagged(from?)` (Next to check, `N`: the next low-confidence note in played order, wrapping). `lastFocusedNoteId` (set by `focusNote`, cleared when the note is gone) is the one record of the focused note: the arrows, `N` and Next to check start from it with nothing selected, and it holds the tab area's tab stop. The UI reads it through `ui/use-take-session.ts`. Story "Change a fret and undo it" (spine AD-4, AD-16): the edit core. `apply(command)` runs the two-phase commands of `model/edit-history.ts` one at a time per take (a promise queue that undo and redo join): it plans against the current Tab revision, maps each planned request to `engineClient.mapFrets`, drops a result whose revision went stale and plans again, and publishes the reduced Tab as one undo step (at most 200, in memory only; reset when a take loads or an analysis replaces the tab). An engine error drops the command and emits a `failed` edit event. `setFret`, `typeDigit` (a second digit on the same note within 400 ms makes one number and merges into the first's step; the clock is injectable), `undo`/`redo` (the selection follows the step's note), `canUndo`/`canRedo`. The edited Tab is saved with a 300 ms debounced `putTab`; `flush()` saves at once, on dispose (not awaited) and on `pagehide` / `visibilitychange` → hidden while active. A `storage-full` save keeps the Tab and sets the snapshot's `saveFailed` (the screen's banner Retry calls `retrySave`); the next successful save clears it; other save errors are logged and retried on the next flush. On `take-deleted` the pending save and queued commands are dropped. `hasUnsavedEdits()` (a save pending or in flight, or a failed one while its screen is open) feeds app-reload.ts's `isAppBusy()`. Edit outcomes go to `onEditEvent` listeners; the Tab screen words and announces them (this layer may not import `ui/`). Dev builds force `storage-full` on every `putTab` with `window.__putTabStorageFullHook`. Story "String moves, delete, insert and confirm": `moveString(noteId, string)` and `moveStringBy(±1)` (↑/↓: the next thinner or thicker string that plays the pitch, via `model/edit-history.ts` `playablePositions`), `deleteSelected()`, `insert()` (after the selection, or before the first note with none; the new note's id comes from the injectable `newId` dep, default `crypto.randomUUID`, and a digit typed before the insert lands sets its fret) and `confirm(noteId)` run through `apply`. A command's `selectAfter` sets the selection once it applies (a delete: the next note in played order, else the previous; an insert: the new note). Commands apply only while the tab is shown; undo and redo also work with no notes left (No notes found) while there is history. A delete's edit event carries the deleted note's string and fret; a command that changes nothing (confirming a confirmed note) emits no event, except a set fret. Story "Analysis settings and re-analysis" (US-4.6, AD-4): `setSettings(patch)` clamps (`model/analysis-settings.ts`) and saves `settings` with `patchTake` at once (published locally; no undo step; a failed write reverts to the stored settings). `reanalyse()` queues like a command (refused with `audio-missing` when the take has neither compressed audio nor a raw file, `hasAudio`; `hasRaw` is read at load through the `hasRaw` dep): `analysis.reanalyse`, then `model/edit-history.ts` `freshNotes` (new ids, low confidence below c + 0.15), `mergeReanalysis` (fresh notes within 50 ms of a locked note or a `deletedStartMs` entry dropped; locked notes kept unchanged), one `mapFrets` with a lock per locked note (`reanalysisRequest`, `placeReanalysed`: an unlocked note with no position is dropped), one `commitAnalysis` (Tab + `warnings`, `analysisVersion`), then `deleteRaw` when the raw file was read. The snapshot's `reanalysis` carries its progress; meanwhile edits, undo and redo do nothing and the undo and redo labels read null. `cancelReanalysis()` cancels it with nothing changed. A finished re-analysis pushes one snapshot step (`{kind: 'reanalyse'}`, no target) of `{notes, deletedStartMs, settings, trimStartMs, trimEndMs, warnings, analysisVersion}`; undo and redo of it restore all seven through `commitAnalysis`. Its `before` settings are `analysedSettings` (the take's at load or first analysis, then each re-analysis's or restore's). Pending edit saves are held while a `commitAnalysis` writes the Tab. Outcomes go to `onEditEvent` as `reanalysed`, `reanalyseCancelled` and `reanalyseFailed`.

settings-session.ts holds the engine status (About) and a `prefs` snapshot loaded with `loadPrefs()` (story "Flags, warnings and bar lines on screen"); `setBarLines(on)` writes `prefs.barLines` through `updatePrefs` and publishes. `subscribePrefs` subscribes without asking the engine for its version, so the Tab screen never starts the engine. recording-session.ts keeps its own `updatePrefs` calls for the mic and count-in fields. Story "Analysis settings and re-analysis": the snapshot's `prefs` also carries `analysisDefaults`; `setAnalysisDefaults(patch)` clamps and writes them (the Settings screen's "Defaults for new takes"), which recording-session copies into each new take.

playback.ts (story "Playback with a following cursor") gives the Tab screen's playback the take's compressed audio (`readTakeAudio`, `audioStore.readCompressed`) and holds the mounted screen's playback controller (`setActivePlayback`/`activePlayback`) for the Space and `P` shortcuts, a sibling of take-session's active-session slot. The playback state itself (the `<audio>` element, speed, the cursor) is UI state in `ui/use-playback.ts` and is never stored.
